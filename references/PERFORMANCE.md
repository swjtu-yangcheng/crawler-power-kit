# PERFORMANCE — 提速与效能优化清单（实战浓缩）

原则：**每一层的成本差一个数量级**。urllib ~0.5s / 页；Crawl4AI ~5s；
Playwright ~8-15s。选错层就是 10 倍以上的浪费。

## 何时用什么（按速度排）

| 场景 | 最快路径 | 典型耗时 |
|---|---|---|
| 静态页、API、JSON 端点 | `quick`（urllib 层） | 0.3–2s |
| 需要干净 Markdown | `md`（Crawl4AI） | 3–8s |
| JS 渲染 / 点击 / 登录态 | `render`（Playwright） | 8–15s |
| 批量 URL 列表 | `batch`（并发 urllib） | N/并发 × ~1s |
| 整站爬取 | Crawl4AI BFS / Scrapy | 看预算 |

## 提速手法（按收益排）

1. **先探 API 再爬 HTML**：robots.txt、sitemap.xml、RSS/Atom、JSON-LD、
   `?format=json` 探测。结构化数据比解析 HTML 快且稳。
   `curl -sL <site>/robots.txt` → `curl -sL <site>/sitemap.xml`
2. **URL 归一化去重先行**：`batch` 已自动去掉 utm_*/fbclid/sid/会话参数、
   尾斜杠、fragment。重复 URL 是最大的隐性浪费。
3. **并发 + 限速的甜点位**：6 并发 × 0.5s 延迟（默认）。再快收益递减且
   容易触发 429。同站并发 ≤ 2。
4. **缓存稳定标识**：任务内同 URL 不重复抓；Crawl4AI 自带 CacheMode。
5. **早停规则**：新结果 70%+ 是重复或低价值时停止扩展； synonym 搜索
   连续两轮无新域名即停。
6. **小样本门（硬性）**：放量前先 1–10 页验证字段完整/翻页有效/时间戳
   合规。爬 1000 页后才发现字段缺失是最大时间黑洞。
7. **代理分层**：本机代理对国内站慢且可能 502——国内站直连；境外站
   走代理；失败自动互换（ladder 已内置）。
8. **截图仅作证据**：文本已结构化可取时不要截图；截图慢 5–10 倍。
9. **浏览器单独升级**：批量任务默认 layer 1；只有抽样失败的 URL 单独
   `quick`（该命令才会走 layer 2/3）。
10. **gzip + 浏览器 UA**：请求头已内置；缺 gzip 的站点流量大 3–5 倍。

## 失败处理决策树

```text
空正文/JS壳     -> quick 自动升级（Crawl4AI→Playwright）
403/429         -> 降速、换引擎、找官方API；绝不硬怼循环
代理502         -> 自动直连重试（已内置）；仍失败=被墙，提示用户开VPN
CAPTCHA/登录墙  -> 硬边界，停；找官方渠道或替代授权源
付费墙          -> 不绕；找摘要/预印本/作者稿/独立报道
```

## 效能自检（每次深度爬取后）

- [ ] 目标字段全部抓到了吗？（缺字段=重爬代价）
- [ ] 翻页真的前进了吗？（page2 ≠ page1 内容）
- [ ] 重复率 < 阈值？
- [ ] 每条记录留痕（URL/时间/方式/层级）？
- [ ] 边际收益还在吗？（最后 20% 的时间花了多少价值）
